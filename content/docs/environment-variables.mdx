---
title: Environment Variables
description: Every variable the app reads, what it's for, and whether it's required.
---

All of these go in `.env` (gitignored) at the project root. `.env.example`
in the repo documents the same list with placeholder values, copy it to
`.env` and fill in real values to get started.

| Variable | Required | Used for |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Yes | Your Supabase project URL. Used by the browser, server and proxy clients. |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Yes | Supabase publishable (anon) key, used for sign-in and session refresh. |
| `SUPABASE_SERVICE_ROLE_KEY` | Yes | Service-role key, **server-only**. Used by `src/lib/supabase/admin.ts` for Storage uploads/downloads. Never expose it to the browser. |
| `DATABASE_URL` | Yes | Pooled (pgbouncer, port 6543) Postgres connection string, used by Prisma at runtime. |
| `DIRECT_URL` | Yes | Direct (unpooled, port 5432) connection string, used by Prisma for migrations. |
| `RESEND_API_KEY` | No | Enables real email sending. Without it, emails just log to the console, see [Email Notifications](/docs/email-notifications). |
| `EMAIL_FROM` | No | The `from` address for outgoing email. Defaults to Resend's sandbox address if unset. |
| `APP_URL` | No | Used to build the "review applicants" link inside the new-application email. Defaults to `http://localhost:3000`. |
| `RAZORPAY_KEY_ID` | For payments | Razorpay API key id. Without the key pair, order creation returns "Payments aren't configured yet". |
| `RAZORPAY_KEY_SECRET` | For payments | Razorpay API secret, also used to verify payment signatures. |
| `RAZORPAY_WEBHOOK_SECRET` | For webhook | Set when you add the webhook (Razorpay dashboard, Settings, Webhooks) pointing at `/api/webhooks/razorpay`. |

## Creating the first admin

There's no seeded account (`prisma/seed.ts` is intentionally empty). Register
a normal account at `/register`, then promote it in the Supabase SQL editor:

```sql
UPDATE "User" SET role = 'ADMIN' WHERE email = 'you@example.com';
```

## Migrations

```bash
npx prisma migrate dev      # local, creates/applies migrations
npx prisma migrate deploy   # production, applies existing migrations
```

Prisma uses `DIRECT_URL` for migrations and `DATABASE_URL` for queries.
